Enterprises rarely run on clean, modern GraphQL APIs. They run on 15-year-old on-premise ERPs, SOAP interfaces, legacy SQL databases with undocumented schemas, and rate-limited CRM endpoints. When businesses attempt to connect modern AI agents directly to these older architectures, the systems often crash or corrupt transactional data. By reading this guide, you will understand how to construct an integration middleware layer that connects probabilistic AI models to legacy systems reliably and safely.

## What is it?

AI-to-legacy integration is an intermediary gateway pattern that translates unstructured natural language intents into validated, deterministic API calls for legacy software:

1. **Schema-Bound Tool Definitions**: Defines explicit JSON schemas for legacy operations (e.g., creating purchase orders or updating warehouse stock) that constrain the model's function-calling capabilities.
2. **Translation & Sanitization Middleware**: Converts the model's JSON parameters into the specific protocol required by the legacy system (e.g., XML/SOAP payloads or raw SQL query parameters).
3. **Idempotency & Circuit Breaking**: Enforces transaction uniqueness keys to prevent double-billing and protects delicate legacy databases from query overload.

```
┌─────────────────────────┐       ┌─────────────────────────┐
│ User Intent or Request  │ ───►  │ AI Model Tool Calling   │
│ ("Reorder SKU-402")     │       │ Emits Validated JSON    │
└─────────────────────────┘       └───────────┬─────────────┘

             ┌────────────────────────────────┴────────────────┐
             ▼ Failed Parameter Check                          ▼ Validated Arguments
┌─────────────────────────┐                       ┌─────────────────────────┐

```

## Why does it matter?

Directly coupling AI agents to legacy business systems introduces major operational hazards:

- **Unpredictable Query Synthesis**: Models allowed to generate raw SQL often construct unindexed `SELECT *` table scans that lock enterprise databases and cause downtime.
- **Protocol Mismatch**: Modern LLMs communicate natively in JSON, while legacy systems frequently require strict SOAP XML envelopes, specific timestamp encodings, and legacy session cookies.
- **Lack of Rollback Capabilities**: If an autonomous agent triggers five consecutive state-altering API requests and the fourth fails, legacy systems without distributed transaction handling leave customer data in an inconsistent state.

An integration middleware layer enforces business guardrails, protects legacy infrastructure, and prevents data corruption.

## How does it work?

A production integration layer relies on strict Pydantic schemas, parameter mapping, and circuit breakers:

### 1. Strongly Typed Tool Definitions
Never allow an LLM to generate unstructured API requests. Provide rigid tool specifications that enforce strict parameter constraints.

```python
from pydantic import BaseModel, Field

class LegacyInventoryOrder(BaseModel):
    sku: str = Field(pattern=r"^[A-Z]{3}-\d{4}$", description="Item SKU in format AAA-0000")
    quantity: int = Field(gt=0, le=500, description="Order quantity between 1 and 500 units")
    warehouse_code: str = Field(description="Target warehouse facility identifier")
    idempotency_key: str = Field(description="UUID to prevent duplicate submissions")
```

### 2. Protocol Translation Middleware
The middleware intercepts the model's structured JSON payload, performs parameter sanitization, and formats the legacy XML envelope.

```python
import xml.etree.ElementTree as ET

def build_soap_inventory_payload(order: LegacyInventoryOrder) -> str:
    soap_body = f"""<?xml version="1.0" encoding="utf-8"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <CreatePurchaseOrder xmlns="http://legacy.enterprise.internal/erp">
      <SKU>{order.sku}</SKU>
      <Quantity>{order.quantity}</Quantity>
      <WarehouseId>{order.warehouse_code}</WarehouseId>
      <TransactionId>{order.idempotency_key}</TransactionId>
    </CreatePurchaseOrder>
  </soap:Body>
</soap:Envelope>"""
    return soap_body
```

### 3. Read Replicas and Circuit Breakers
Route all AI-generated informational queries to read-only database replicas rather than production master nodes. Implement circuit breakers that throttle incoming agent queries if legacy response latency spikes beyond normal thresholds.
