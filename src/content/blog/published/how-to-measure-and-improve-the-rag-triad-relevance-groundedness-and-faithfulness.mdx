When a Retrieval-Augmented Generation (RAG) system outputs an incorrect or unhelpful answer, developers frequently make the mistake of treating the pipeline as a monolithic black box. They tweak the prompt, switch between model providers, or adjust temperature settings in the hopes that accuracy will magically improve.

This trial-and-error approach wastes weeks of engineering time because it fails to diagnose where the failure actually occurred:
- Did the vector database retrieve irrelevant document chunks?
- Did the retrieval succeed, but the foundation model hallucinated outside the context?
- Or did the model summarize the context faithfully, but fail to directly answer what the user asked?

To systematically improve application accuracy, production AI engineering teams decompose evaluation into three independent, quantifiable dimensions known as the **RAG Triad**: Context Relevance, Groundedness (Faithfulness), and Answer Relevance.

Here is how modern software teams measure and elevate each pillar of the RAG Triad.

```
┌────────────────────────────────────────────────────────┐
│ The RAG Triad Diagnostic Architecture                  │
│                                                        │
│                    [User Query]                        │
│                     ▲        ▲                         │
│                     │        │                         │
│   Context Relevance │        │ Answer Relevance        │
│   (Retrieval Metric)│        │ (End-to-End Metric)     │
│                     ▼        ▼                         │
│            [Retrieved Context] ──► [Generated Answer]  │
│                     ▲                      ▲           │
│                     └──────────────────────┘           │
│                           Groundedness                 │
│                        (Generation Metric)             │
└────────────────────────────────────────────────────────┘
```

## Pillar 1: Context Relevance (Evaluating Retrieval)

**Definition**: Measures what percentage of the retrieved context chunks are directly necessary and relevant to answering the user's question.

- **The Problem It Diagnoses**: If your context relevance is low (e.g., scoring 0.45), your retriever is returning noisy, bloated text fragments. Even if the answer is contained somewhere in the text, excess noise distracts the LLM's attention mechanism and bloats token expenses.
- **How It Is Calculated**: An automated evaluator inspects each retrieved sentence or chunk and calculates the ratio of relevant sentences to total retrieved sentences: `Context Relevance = (Relevant Sentences in Context) / (Total Sentences Retrieved)`.
- **Engineering Fixes to Improve Context Relevance**:
  - **Smaller Chunk Sizes**: Transition from 1,000-token chunks to 250–350 token chunks with 50-token overlaps.
  - **Cross-Encoder Reranking**: Retrieve top-30 candidates with vector search, but pass them through a cross-encoder (e.g., Cohere Rerank) to filter down to the top 4 highest-relevance chunks.
  - **Hybrid Search**: Combine dense vector embeddings with BM25 keyword search to ensure exact alphanumeric codes and product terms are captured accurately.

## Pillar 2: Groundedness / Faithfulness (Evaluating Generation)

**Definition**: Measures whether every factual claim in the generated response can be directly inferred from the retrieved context chunks, without introducing outside hallucinations.

- **The Problem It Diagnoses**: If context relevance is high but groundedness is low (e.g., 0.60), your retriever did its job, but your generative model is hallucinating. It is using its pre-training weights to speculate on facts rather than adhering to the source text.
- **How It Is Calculated**:
  1. Break the generated answer down into individual atomic claims.
  2. For each claim, check whether it is logically entailed by the retrieved context.
  3. `Groundedness Score = (Verified Claims) / (Total Claims in Answer)`.
- **Engineering Fixes to Improve Groundedness**:
  - **Strict Grounding Prompts**: Prohibit the model from assuming facts: *"If the provided context does not contain the answer, state clearly that the documentation lacks sufficient details."*
  - **Bracketed Chunk Citations**: Force the model to attach source chunk IDs (e.g., `[Chunk 2]`) to every factual claim.
  - **Lower Temperature**: Reduce inference temperature to `0.0` or `0.1` for factual enterprise tasks.

```python
        "groundedness": groundedness,
        "answer_relevance": answer_relevance,
        "overall_triad_health": (context_relevance + groundedness + answer_relevance) / 3.0
    }
```

## Pillar 3: Answer Relevance (Evaluating Usability)

**Definition**: Measures whether the generated response directly and completely answers the user's question, without drifting off-topic or including unnecessary conversational fluff.

- **The Problem It Diagnoses**: An answer can be 100% grounded in the context, but still score zero on answer relevance if it dodges the question or regurgitates irrelevant background paragraphs.
- **How It Is Calculated**: Use the generated response to synthetically reverse-engineer potential questions using an LLM. Compare the semantic similarity of the reverse-engineered questions against the user's original query.
- **Engineering Fixes to Improve Answer Relevance**:
  - **Direct Answer Directives**: Instruct the model to provide the direct answer in the very first sentence before elaborating on supporting evidence.
  - **Query Rewriting**: If the user submits an ambiguous or underspecified prompt in a multi-turn chat (*"What about the second one?"*), rewrite the query using prior conversation history into a standalone, explicit prompt before retrieval.

## Diagnostic Action Matrix

By monitoring the RAG Triad scores across your test suite, your engineering team can identify the exact bottleneck in seconds:

- **High Context Relevance + Low Groundedness**: Generation issue. Model is hallucinating. Tighten prompt constraints or lower temperature.
- **Low Context Relevance + Low Groundedness**: Retrieval issue. The retriever fetched irrelevant text, forcing the LLM to hallucinate. Tune chunking, add hybrid search, or install a reranker.
- **High Groundedness + Low Answer Relevance**: Alignment issue. The model is summarizing the text accurately, but failing to address the user's core intent. Refine instructions to prioritize concise, direct answers.

## Key Takeaway

Stop treating RAG accuracy as a single mysterious number. By measuring Context Relevance, Groundedness, and Answer Relevance independently, engineering teams pinpoint exact architectural bottlenecks and elevate production AI reliability with surgical precision.
