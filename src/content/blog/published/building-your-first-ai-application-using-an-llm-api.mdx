When beginning your journey into AI engineering, tutorials often nudge you toward installing complex frameworks with hundreds of dependencies. While those frameworks have their place, starting with them obscures how large language models actually communicate over the network.

At their core, modern foundation models (such as OpenAI GPT-4o, Anthropic Claude 3.5 Sonnet, or Google Gemini) are stateless HTTP web services. You send an array of conversation messages formatted in JSON; the server returns an updated message payload or streams tokens over a Server-Sent Events (SSE) connection.

In this guide, we will build a production-ready, asynchronous AI backend service from scratch using Python, FastAPI, and the official OpenAI SDK—complete with streaming tokens, system role framing, and error handling.

---

### Understanding the 3 Core Roles in Chat Completions

Every request sent to a modern chat model accepts an array of message objects. Each message must declare a specific `role`:

```
[The Three Chat Message Roles]

1. "system" (The Behavioral Anchor)
   - Defines the persona, constraints, style, and guardrails.
   - Example: "You are an expert technical editor. Never use marketing buzzwords."

2. "user" (The Human Input)
   - Contains the real-time prompt, task, or question from the end user.
   - Example: "Review this pull request description for clarity."

3. "assistant" (The Model's Output / Conversation Memory)
   - Represents previous responses generated by the model.
   - By appending assistant messages alongside user messages, you build conversational context.
```

### Step-by-Step Implementation

#### 1. Environment Setup

Create an isolated virtual environment and install our core production dependencies:

```bash
python3 -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate
pip install fastapi uvicorn openai pydantic
```

Store your API key in an environment variable rather than hardcoding it into Python files:

```bash
export OPENAI_API_KEY="your-api-key-here"
```

#### 2. Building the Asynchronous FastAPI Service

Create a file named `main.py`. We will implement a streaming endpoint that receives a user prompt and streams tokens back to the client in real time:

```python
import os
from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
from pydantic import BaseModel, Field
from openai import AsyncOpenAI

app = FastAPI(title="Minimal Production AI Microservice")

# Initialize the asynchronous client
client = AsyncOpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

class ChatRequest(BaseModel):
    prompt: str = Field(..., min_length=1, max_length=2000)
    temperature: float = Field(default=0.2, ge=0.0, le=2.0)

@app.post("/v1/chat/stream")
async def stream_chat(request: ChatRequest):
    try:
        # Create an asynchronous streaming completion
        response = await client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[
                {
                    "role": "system",
                    "content": "You are a pragmatic senior software architect. Provide direct, concise technical explanations."
                },
                {"role": "user", "content": request.prompt}
            ],
            temperature=request.temperature,
            stream=True
        )

        async def token_generator():
            async for chunk in response:
                content = chunk.choices[0].delta.content
                if content:
                    # Format as Server-Sent Events (SSE) data chunks
                    yield f"data: {content}\n\n"

        return StreamingResponse(token_generator(), media_type="text/event-stream")

    except Exception as e:
        raise HTTPException(status_code=500, detail=f"LLM Provider Error: {str(e)}")
```

#### 3. Running and Testing the Server

Start your microservice with hot reloading enabled using `uvicorn`:

```bash
uvicorn main:app --reload --port 8000
```

Open a second terminal window and test the streaming endpoint using `curl`:

```bash
curl -N -X POST http://127.0.0.1:8000/v1/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Explain database indexes in two sentences.", "temperature": 0.2}'
```

You will see tokens arrive in your terminal one by one with negligible latency.

### Key Hyperparameters You Must Master

- **`temperature` (0.0 to 2.0):** Controls output randomness.
  - Set to `0.0` or `0.2` for structured JSON extraction, coding tasks, and deterministic factual queries.
  - Set to `0.7` to `1.0` for creative writing and brainstorming.
- **`max_tokens`:** Binds the maximum completion length. Always configure a reasonable cap to prevent runaway token spend on unexpected edge cases.
- **`top_p` (Nucleus Sampling):** An alternative to temperature. It restricts candidate tokens to the top probability mass. Best practice: modify either `temperature` or `top_p`, but never both simultaneously.

---

### Common Pitfalls to Avoid

- **Synchronous Client in Async Routes:** Never use the standard `OpenAI()` client inside an `async def` FastAPI route. Always use `AsyncOpenAI()` to prevent blocking the Python event loop.
- **Missing Timeout Configurations:** Upstream providers occasionally experience latency spikes. Always configure network timeouts (e.g., `timeout=15.0`) on client calls.
- **Ignoring Streaming on Interactive UIs:** If your feature serves an interactive user interface, always use streaming. Forcing users to wait 5 seconds for a non-streamed response destroys perceived quality.
