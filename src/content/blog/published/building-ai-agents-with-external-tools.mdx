The transition from a standard conversational chatbot to an **AI Agent** marks the shift from passive text generation to active environmental interaction. A chatbot can summarize a document or write an essay; an agent can check your cloud infrastructure status, query an external SQL database, calculate a financial margin, and send an alert to a Slack channel.

To build reliable agents, you do not need 5,000 lines of complex orchestration framework code. An agent is fundamentally a model operating inside a deterministic control loop: it analyzes an objective, chooses an available tool, inspects the tool's execution result, and decides whether to take another action or reply to the user.

```
The Agent Execution Loop (ReAct Pattern):

[ User Goal ]
      |
      v
[ LLM Evaluation ] <------------------------------------+
      |                                                 |
      +---> [ Decision: Call External Tool? ]           |
                  |                                     |
                  +--- (Yes) ---> [ Execute Function ] -+
                  |               (Local Python / API)
                  |
                  +--- (No)  ---> [ Final Response to User ]
```

---

### 1. How Tool Calling Works Protocol-Level

Modern LLMs (such as GPT-4o, Claude 3.5 Sonnet, and Gemini 1.5 Pro) do not execute Python code on their own servers. Instead, you declare the functions your backend supports as a JSON Schema.

When the user asks a question requiring external information, the model detects the schema match and outputs a structured JSON payload detailing which function to call and with what arguments. Your application executes the function locally and sends the return value back to the model as a `tool` message.

---

### 2. Defining Tools Using Clean Schemas

Here is how you define a tool schema for a currency conversion utility and weather lookup:

```python
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_stock_price",
            "description": "Fetch the current trading price for a stock ticker symbol.",
            "parameters": {
                "type": "object",
                "properties": {
                    "ticker": {
                        "type": "string",
                        "description": "The stock market symbol, e.g. AAPL, MSFT, GOOG"
                    }
                },
                "required": ["ticker"]
            }
        }
    }
]
```

Next, define the local Python implementation that will perform the real work:

```python
def get_stock_price(ticker: str) -> str:
    # Simulated API response (in production, call your financial data provider)
    prices = {"AAPL": "189.45 USD", "MSFT": "428.10 USD", "GOOG": "176.20 USD"}
    return prices.get(ticker.upper(), f"Error: Ticker '{ticker}' not found.")

# Dispatch table mapping tool names to callable Python functions
TOOL_REGISTRY = {
    "get_stock_price": get_stock_price
}
```

### 3. Implementing the Autonomous Execution Loop

Now, let us wire the model and the tools inside an iterative loop. Notice the safeguards: we set a maximum iteration limit (`max_iterations = 5`) to prevent runaway API spend.

```python
import json
from openai import OpenAI

client = OpenAI()

def run_agent(user_prompt: str, max_iterations: int = 5) -> str:
    messages = [
        {"role": "system", "content": "You are a helpful financial assistant with tool access."},
        {"role": "user", "content": user_prompt}
    ]

    for iteration in range(max_iterations):
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages,
            tools=tools,
            tool_choice="auto"
        )
        
        response_message = response.choices[0].message
        messages.append(response_message)

        # Check if the model opted to call one or more tools
        if not response_message.tool_calls:
            # Model finished reasoning and returned final text
            return response_message.content

        # Handle requested tool calls
        for tool_call in response_message.tool_calls:
            function_name = tool_call.function.name
            function_args = json.loads(tool_call.function.arguments)
            
            if function_name in TOOL_REGISTRY:
                tool_output = TOOL_REGISTRY[function_name](**function_args)
            else:
                tool_output = f"Error: Tool '{function_name}' is not recognized."

            # Feed the tool execution result back into the message history
            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": str(tool_output)
            })

    return "Agent aborted: Maximum iteration limit reached."
```

If we execute:

```python
print(run_agent("How much is Apple stock right now, and what would 10 shares cost?"))
```

The model first invokes `get_stock_price(ticker="AAPL")`, receives `"189.45 USD"`, calculates the math internally, and outputs the final message:

```
Apple stock (AAPL) is currently trading at $189.45. Purchasing 10 shares would cost $1,894.50 USD.
```

### 4. Three Production Vulnerabilities in Agent Systems

When moving agents into production, you will encounter failure modes that standard web apps never face:

- **1. Infinite Tool Churning**: Models sometimes get confused by vague tool errors and call the same failing function repeatedly with slight argument variations. Always enforce hard loop caps (`iteration <= 5`) and per-session cost budgets.
- **2. Schema Hallucination**: The model might invent parameters not present in your schema. Wrap all tool execution calls with Pydantic validation: if arguments fail validation, catch the `ValidationError` and feed the error string directly back to the model so it can self-correct.
- **3. High Latency Overhead**: Every tool loop step represents an independent sequential round-trip to the model provider. If your agent requires 4 tool invocations, your user will wait 4 to 8 seconds. Where possible, instruct the model to call parallel tools in a single response turn.

---

### Summary

Agents are not mysterious autonomous beings; they are deterministic while-loops wrapped around structured LLM function calling. By keeping your tool schemas concise, implementing strict iteration bounds, and validating arguments with Pydantic, you can build reliable agentic systems that run predictably in production.
